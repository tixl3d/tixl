# TiXL v4.4 - Release Notes (WIP)

## Support for Mac, Linux and Windows

With v4.4 a dream comes true. We have been working towards this step for several years, but with the new Vulkan abstraction layer these efforts finally show a remarkable result: TiXL is truly cross-platform. With very few exceptions, all projects, operators and examples work on all platforms. All project file formats are compatible and you can freely jump between them.

## Installation
- On [Linux](https://github.com/tixl3d/tixl/blob/feat/linux-port/.help/docs/install/InstallLinux.md) (including a Nix package for NixOS)
- On [macOS](https://github.com/tixl3d/tixl/blob/feat/linux-port/.help/docs/install/InstallMacOS.md)



## Rendering on Vulkan

You don't need to understand the technical background to create projects with TiXL and can skip this section.

### Why we can't rely on Windows

On Windows, TiXL was using the Windows graphics API DirectX to render with your graphics card. For reasons that only Microsoft's management knows, it never created an API to access DirectX from C#, so the ecosystem had to rely on SharpDX - an open source project by [Alexandre Mutel](https://github.com/xoofx) - until he retired the project a couple of years ago. At the same time, Microsoft tried to compete with Metal and Vulkan and created a completely new version 12 of DirectX -- again without any support for C#. To make things worse, newer versions of DX11 were limited to Windows 11.

Additionally, driven by recent decisions from Microsoft and the increasing instability and slowness of the platform, we have seen a significant movement of creatives and developers towards alternative platforms. The only way forward was to use a new graphics API: Vulkan.

Just like DX12, Vulkan is extremely awkward to work with: It's verbose, low-level and finicky. But there is excellent cross-platform support. And there are a few things that made porting TiXL easier than we expected:
- 95% of all user interface code is using ImGui and C#. So the UI runs out of the box on all platforms (this was the primary reason for using the framework many years ago).
- TiXL is using C# and the dotnet ecosystem, which has good support on all our target platforms. And over the last years we tried very hard to only use NuGet packages that are cross-platform compatible.
- Slang is a new shader compiler that compiles TiXL's DirectX shader code from HLSL into Vulkan's SPIR-V with very few, non-breaking changes.
- TiXL has very few operators that use DirectX-specific types directly. Most of these building blocks are wrapped away.
- Over the years we have built and maintained a set of visual reference tests: Small images rendered once and used to test feature compatibility and avoid regressions.

Where we're standing now:

TiXL is running extremely well on Linux and macOS. Normal startup time is 1-2s (compared to 10-20s on Windows). Framerates are more stable and Vulkan rendering performance is on the same level. 

All your projects should work. But if you've written custom shader code, there are [a few modifications you might have to make](https://github.com/tixl3d/tixl/blob/feat/linux-port/.help/docs/advanced/UpgradingToVulkan.md). Custom operators written against SharpDX types are rewritten automatically the first time a project opens; the same page describes what that covers.


## Improved UI Scaling

Testing on all three platforms allowed us to improve a lot of layout details related to UI scaling. With Wayland and macOS we can't rely on 96 dpi anymore. So a lot of time went into tweaking font resizing, handling multi-display setups with varying DPIs, adjusting scaling on the fly, etc.

## Trackpad Support

Trackpad support on Windows is extremely limited because most notebook manufacturers use mouse simulation instead of providing access to the touch events. With macOS and Linux this situation improved significantly, so we now have proper pinch zoom and flicking, and all the other fancy things you expect from a nice trackpad.

## Better Framerate Support

We also spent a lot of time supporting different refresh rates. This became more urgent with setups that use multiple displays (e.g. 240 Hz on a MacBook display with an external projector running at 60 Hz). In many areas TiXL was relying on 60 Hz for smoothing animations. We now infer the refresh rate of the primary display the editor is running on.

## Screen Space Reflections

- [ScreenSpaceReflections] adds reflections of what is visible on screen, using the depth and normal buffers of [RenderTarget].
- [ScreenSpaceAO] darkens creases and contact areas with short rays through the same buffers, and can tint them with color bleeding.
- [ScreenSpaceLighting] combines both with one set of inputs.

## Cube Maps

- [RenderToCubeMap] renders a scene into a cube map, with MSAA and TXAA.
- [RaymarchToCubeMap] raymarches SDF fields into a cube map. Cube maps also support the EAC layout.

## Output Setup

- The editor UI can be added as content and mapped onto a display, replacing the old 2nd render window and its "Mirror UI on second view" setting.
- An output's projector camera can be solved from a surface aligned on it (**Solve from Calibrated Surface**, with the lens shift from the projector's spec), so [UseProjectorCam] places 3D content without hand-entered numbers. Surfaces get a **Facing** preset (Wall, Floor, Ceiling). While a surface is being calibrated, the camera solved from it follows the aimed points, so 3D content lines up live.
- **Connect...** → **New 3D Content** draws a surface in 3D through its projector's solved camera, with its photo on it, as the output's front layer; objects added beside it land on and in front of the real wall. The new [SurfaceGeometry] op is the surface as a quad in the stage. What Connect... builds comes from editable template symbols in Lib.
- An output's card lists its **Layers**, front first: its surfaces and patches, reordered by dragging, each with a blend mode (Normal, Add, Multiply, Screen), opacity and tint, and an × to disconnect. Patches can now draw over surfaces.
- [SendToOutput]: **Size From** is now **Resolution From**, with the surface options first, and **Resolution** is now **Resolution Override**.
- **Align Points** is now called **Calibrate**. On a game controller the left trigger turns the pin a quarter clockwise, for a projector on its side; the right trigger alone shows the photo inverted.
- Disconnecting a surface from an output keeps its alignment; connecting it to the same output again restores it.
- **Connect...** on a surface or region without content builds a scene around its reference photo: the new [SurfaceReferenceImage] op shows the straightened photo as a design guide, and [SendToOutput] can take its size from the surface: **Surface Aspect** keeps a stable height, **Projected Surface** matches the projector's pixels, and **Resolution Factor** scales either.
- In the output setup outliner, input slots show whether an item takes one connection (dot) or several (pill). Dropping onto an output or patch adds a connection on its "+" side and replaces all its connections on the rest.
- Aligning by reference points is steadier: the four points spread furthest apart define the corner pin, further points only refine it and are shown faded while they disagree.
- The gamepad's shoulder buttons step through the outer reference points first, and small stick movements move a point much more precisely.

## Audio

TiXL has a new audio engine, built on the open source miniaudio library, and no longer includes BASS. Using TiXL commercially doesn't need a BASS license anymore.

- Audio input on Linux can capture what other apps play (`Monitor of ...` devices), and other apps can use a microphone at the same time.
- Audio runs about 100 ms earlier than before. Projects with an audio offset tuned to the previous version may need adjusting, and a selected input device may need to be picked again.
- Spatial audio shows up in meters and [AudioReaction], exports the way it sounds live, and has no practical limit on sources. Distant sources are louder than before, and a centred source is a little quieter.
- [AudioFilter] is a new low-pass and high-pass filter, and [AudioToneGenerator] has a panning input.
- Any single source can be metered and analysed with [AudioLevel] and [AudioReaction], also as a side branch.
- [AudioReverb], [AudioEcho] and [AudioCompressor] now work on every platform, not only Windows. They are new implementations, so they sound somewhat different from before.
- AAC, M4A and WMA files are no longer supported. Use WAV, MP3, OGG or FLAC.

## Other Improvements

- Connected MIDI devices are detected automatically when they are plugged in or removed.
- NDI input and output work on Linux once the NDI runtime is installed (see the Linux install guide).
- Game controllers and the SpaceMouse work on Linux. Both can fly the camera of the output: *Settings → Input Devices* (formerly *Space Mouse*) shows their connection and chooses between camera and operators. The new [SpaceMouse] operator reads the SpaceMouse like [Gamepad] reads a controller.
- `VideoDeviceInput` is now called [WebcamInput] and also captures webcams on Linux. It runs on SDL on every platform, so its native settings dialog is gone and the default mode is the largest one up to 1080p.
- Dragging a timeline clip's start or end handle shows the frame at that edge in the output, while the playhead stays in place.
- Camera rotation with a trackpad is less sensitive.
- The parameter popover can search file and folder paths in the assets and set any other text parameter by typing.
- The arrow keys and the parameter popover (`S`) work from any window. Over a focused Output Window with a camera, `S` still moves the camera.
- `Esc` brings the keyboard focus back to the graph from any other window, so graph shortcuts work again without clicking into it.
- The debug bridge can be started from the settings.
- The splash screen is sharp on high-resolution displays.
- *Settings → Interface → Max Fill Resolution* limits the render resolution of outputs that fill their window, such as focus mode, to keep high-resolution displays fast.
- Without a Parameter Window (e.g. in focus mode), the parameter popup no longer opens when an operator is created or first clicked, so arrow-key navigation and `S` keep working. Click an already selected operator again, or middle-click it, to open the popup.
- Shader compile errors show the line, the file and the identifier or types involved, plus a hint for common causes when upgrading older shaders.
- The camera locked in the output window's camera dropdown is saved with the project.
- Window layouts keep the proportions of their panels on any display size and when the app window is resized. Before, only the graph window grew or shrank and every other panel kept its width in pixels.
- **Help > Show Folder** opens the projects, settings, cache, temp and log folders, and **Help > Logs** shows the sessions of the last 7 days, marks the ones that crashed or ended unexpectedly, and can share them with the developers.
- A grayed-out **Export as Executable** in the main menu explains on hover what is missing: a selected operator, or a [SendToOutput] inside it.
- The new [OffsetCurves] operator grows or shrinks curve outlines with sharp, round or beveled corners. [StringToCurves] (formerly TextToCurves) has grouped parameters, **Position** and **LetterSpacing** parameters, and [CurvesToPoints] rotates its points to face away from the outline.
- [ExtrudeCurves], which sweeps a profile of GPU points along a rail, is now called [ExtrudePointCurves], and [CurvesToGeometry] takes its name: [ExtrudeCurves] fills and extrudes curves. Existing graphs keep working.
- CPU geometry and curves are one type, **Geometry**: points and primitives (polygons and bezier curves) with attributes on points, vertices, primitives, edges and parts. All geometry operators accept both; the new [SelectGeometry] selects elements by pattern or C# snippet, and [TransformGeometry] can move each point in its own orientation and respects selections. Existing graphs keep their connections.
- The new [CustomGeometryAttribute] writes a named attribute on points, vertices, primitives or parts from a C# snippet, blended by a selection; [AttributeFromField] writes one by sampling a scalar field.
- The new [ColorGeometry] colors points, vertices, primitives or parts from a gradient, driven by an attribute, the element index, a random value or a field, with the Mapping, Range and Phase of [MapPointAttributes] plus gain, bias and randomization. Point colors now also reach meshes and [CurvesToPoints].
- The Output Window shows geometry, point buffers and point lists with a sidebar: one segmented control hides it or picks a table per domain (points, vertices, edges, primitives, parts) or the stats, a splitter sizes it, and the render moves into the area next to it. Hovering a row marks its element on the render.
- The new [SubdivideGeometry] splits polygons into quads, with a Smoothness from linear (0, to add points for displacement) to Catmull-Clark (1), optionally scaled per point by an attribute such as a selection. UVs, parts and curves are kept. It can also refine adaptively: LevelAttribute (e.g. a selection) or MaxEdgeLength choose which faces get subdivided, and the surface stays closed at the borders.
- [GeometryToMesh] fills closed curves flat, so [StringToCurves] -> [GeometryToMesh] renders text without an extrusion. The new [FillCurves] outputs that flat fill as geometry for further modelling.
- [ExtrudeCurves] can scale its depth per letter or part with DepthAttribute, e.g. from a [CustomGeometryAttribute] snippet for an animated depth wave.
- [CubeGeometry] has Segments to split each face into a grid, with separate counts along X, Y and Z.
- [BevelGeometry], [TriangulateGeometry], [SeparateLooseParts] and [VoronoiFracture] keep curves in the geometry instead of dropping them, and [TriangulateGeometry] keeps per-face attributes like colors.
- Selection inputs of geometry ops list the input's attributes as you type and show what an empty value means: `<Auto: Selection>` uses an upstream selection, `<All>` ignores it.
- The C# snippets of [SelectGeometry] and [CustomGeometryAttribute] read attributes as `@Name`, e.g. `return @Weight > A;` or `@Color.X`. Attributes of other domains are converted, e.g. `Vector3.Normalize(@Normal)` on primitives averages the vertex normals of each face; the Code field notes which attributes were converted.
- Code fields of the Custom* ops and the C# snippet ops show compile errors directly below the code, with an error border and the line number counted within that field.
- [SelectGeometry] has a Count to select only that many elements from Offset, and the Output Window shows selected primitives as filled faces and parts as outlines.
- For operator developers: the namespace `T3.Core.Utils.Geometry` (`GraphicsMath`, `Ray`, the vector and matrix extensions) is now `T3.Core.Utils.Math3d`, freeing the name for the new `Geometry` type. Operator packages that import it need their `using` updated.
- The new [FlashPointAttributes] operator flashes color, size, position or rotation onto selected points on a trigger and lets them fade back to the incoming points.
- The new [DrawLinesShaded] operator draws lines as PBR-shaded tubes for just two triangles per segment: each segment is a camera-facing quad that ray-traces a round-capped tube, so tubes stay perfectly round at any distance and joints stay clean even at sharp bends. **Smoothing** averages neighbouring points to remove jaggy corners.
- [DrawTubes] was reworked. Tubes now follow each line without twisting, so point rotations are no longer needed, and corners with duplicate points no longer break into fans. **Miter** keeps the full width at sharp corners, **CloseEnds** and **CapInset** close line ends with pointy or flat caps, and **FlatAround** and **FlatAlong** blend to faceted shading. **TextureMode** maps textures by point order, a point attribute, or the distance along each line or across all lines, with **TextureRange**, and **Twist** follows the same coordinate. The tubes also write velocity for motion blur. The sub-segment, distance fade and per-axis stretch options were removed.
- The new [RepeatTransform] operator draws a subgraph several times, either applying the transform once more per copy for spirals and stacks, or interpolating towards a final transform with gain and bias. A gradient colors the copies, scatter randomizes them, an animated index offset scrolls them endlessly, and Strength fades the whole effect in or out.
- The new [MeshBoxProjectUV] operator box-projects UVs onto a mesh, so walls, floors and ceilings all get an undistorted texture without mirroring.
- [LoadAnimatedGltf] shows the complete wiring for playing a glTF animation clip, and the [Character Animation](../docs/using/CharacterAnimation.md) and [Procedural Geometry](../docs/using/ProceduralGeometry.md) help pages are extended and marked as experimental.
- Gradient parameters have an options icon that opens their menu. Its new **Edit Gradient...** opens a resizable popup with a larger gradient and an optional list of the steps, for exact positions, colors and removing steps. Ctrl+click the icon to open the popup directly.
- Each preset in the Parameter window's preset dropdown has a gear menu to write the current values into it, rename it, update its thumbnail or remove it.
- The Output Window shows GPU point buffers as points, drawn like a [VisualizePoints], or as a table of their values with a start index and count. Values that changed since the last frame are tinted orange when they grew and blue when they shrank. Other buffers can be listed as tables too, and all show their count, stride and size. The list of [ReadPointsFromGpu] tints changes the same way and fades zeros instead of drawing them black. Both tables preview color fields with a small strip.
- The Output Window renders CPU point lists, curves and geometry directly, without adding draw ops. Geometry, with curves and polygons drawn together, can also be switched to its stats and to a table of its points, vertices, primitives, edges or parts with all attributes. Rows selected in the table are highlighted on the render, and points selected by [SelectGeometry] are ringed. Transform gizmos no longer draw distorted behind tables and stats.
- Texture format dropdowns list the common formats first with a readable name like *RGBA 16-bit float*, are limited to half the screen height, and disable formats the graphics backend can't create, with a hint why.

## Fixes

- The preset and snapshot dropdowns no longer show a row as hovered when they open without a selection.
- Changed text, checkbox and gradient parameters now count as modified against presets and snapshots, so a preset no longer shows as matching when only its shader code or a gradient differs.
- Back faces of meshes drawn with Culling set to None are now shaded with their normal facing the viewer, so they light correctly and work with screen space reflections and AO.
- [DrawLines] with depth writing and normal blending now writes a camera-facing normal, so screen space reflections and AO no longer cover the lines.
- [DrawRibbons], [DrawMeshAtPoints2], [DrawMeshChunksAtPoints], [DrawMeshWithShadow], [DrawMeshCelShading], [DrawMeshHatched], [DrawTubes] and [DrawPointSpritesShaded] now write their normals, so screen space reflections and AO treat them like [DrawMesh].
- Invalid values (NaN) in the rendered image no longer spread across the screen through the history of [TXAA], [ScreenSpaceReflections], [ScreenSpaceAO] and [ScreenSpaceLighting].
- [SetAttributesWithPointFields] no longer writes random sizes and orientations on Vulkan (Linux and macOS), which broke [DrawMeshChunksAtPointsExample].
- The output setup's size raster is never projected by an exported show, and a surface's measuring lines have their own **Show measuring lines** switch instead of riding the raster's.
- Pinning an op that feeds a [SendToOutput] in the Output window's Fill mode renders it at the size the output setup pulls the send at, so render targets and feedback buffers upstream are no longer resized, and feedback reset, every frame.
- Exported videos now contain every audio clip heard during playback, not just the main soundtrack, and respect a clip's mute.
- Video and image sequence exports no longer wait for the display's refresh, so light scenes render much faster. Realtime continuous capture stays paced.
- Videos exported at fractional frame rates like 29.97 fps keep that rate instead of being stamped as 30, and their audio stays in sync.
- Running out of GPU memory on Vulkan no longer crashes the editor.
- Picking a texture format that can't be rendered into on Vulkan, such as `R32G8X24_Typeless`, `R32G32B32_Float` or a depth format, no longer crashes the editor. The texture stays empty and the log names the format.
- Faster clearing of render targets on Vulkan, which mostly helps integrated GPUs and multisampled targets.
- Smoother frame pacing on Linux with output windows at a different refresh rate.
- On Linux desktops without XDG variables, settings, cache and projects no longer end up in the current folder.
- MIDI and snapshot blending with the APC Mini MK2 on Linux.
- The visual test suite ([AllTests]) now works in released builds, and missing reference images or failed comparisons no longer count as passes.
- [MovingPoints] with [RenderToCubeMap] and [ReadPointsFromGpu] on Vulkan.
- Save and Exit no longer gets stuck after accidental changes to read-only operators.
- A video clip trimmed or played past the end of its footage holds the last frame instead of logging FFmpeg decode errors.
- The parameter popup of an operator no longer collapses to its toolbar when the UI is scaled up, for example in focus mode on high-resolution displays.
- The trim handles of timeline clips grow with the UI scale, so they are easier to grab on high-resolution displays.
- The timeline scrolls when a dragged clip, keyframe, range handle or the playhead nears its left or right edge. Clips dragged past the edge no longer drop out of the drag.
