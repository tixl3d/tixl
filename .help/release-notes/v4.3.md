# TiXL v4.3 - Release Notes (WIP)

v4.3 will be the last release built on DirectX 11. It's a big one: a complete output and projection mapping setup, audio graphs, video editing, procedural geometry, character animation and keyboard control for most of the editor. The next version, v4.4, will run on Windows, Linux and macOS.

## Output Setup and Projection Mapping

The new **Output Setup** is where a project meets the room: it maps what your graph renders onto the displays, projectors and video streams of a venue. Use it for projection mapping onto walls and objects, for multi-display installations, and for sending a rendered canvas to other applications over Spout or NDI. Open it from the last button of an **Output window**, with **Edit Output Setup** in the TiXL menu, or by pressing **O**. See [Output Setup](../docs/using/OutputSetup.md).

- [SendToOutput] publishes content from anywhere in your graph. Content can be cut into slices, which are placed on surfaces and mapped onto outputs.
- The board shows content, surfaces and outputs side by side. Items can be dragged, snapped, renamed inline, rotated, scaled, cropped and duplicated by dragging. The flow outliner below lists the setup along its content flow and supports fence selection.
- Projection mapping with corner pinning, distortion handles, measurement grids, a straightened view, projector calibration from reference images (including pixel maps), and projecting from a view.
- Stage floor plans describe the room in metres: walls with edge lengths, height overrides and editable origins; walls can be lifted from the ground. [StageGeometry] provides the stage as geometry, and [ProjectOntoStage] projects content onto it with filtering.
- **Create Wallpaper Layout** cuts one content strip into a slice per wall, in the order the walls stand around the room, so typography or other content runs continuously around the corners.
- Outputs are bound per machine: attached displays are detected and Spout or NDI senders can be added and configured. Setups are saved with the project, the machine bindings separately, so a show can move between computers.
- A single fullscreen output window per display replaces the old window manager.
- Full undo and redo, and **P** closes the setup again.

## Audio Graphs

Similar to shader graphs you can now create audio graphs. Under the hood, these are related problems because TiXL first have to collect the required and operators and then keep updating them. For this we added a new `Audio Graph Node` connection type. And similar to Raymarch Field we introduced the new [AudioBus] operator. This is huge,  because this unlocks multiple soundtracks, audio effects (e.g. [AudioReverb], [AudioEcho],  audio pipelines with side chaining and ducking [AudioLevel], [DuckAudioLevel] etc.).

## New Project Soundtrack

With the new audio pipeline come a much more powerful [AudioClip]. This replaces TiXL's project soundtrack: Old projects will be updated automatically and their main soundtrack we be replaced with an "AutoPlay" AudioClip. This unlocks a bunch of new features such as:

- You can animate the audio volume
- Have multiple project project soundtracks
- Customize how a project soundtrack should looks.
- Audio files can be dragged onto the timeline to create audio clips

## Editing Video and TimeClips

Okay - I admit: I hate creating release videos. So the only logical reason for this is that editing with Premiere is not fun and we need video editing capabilities in TiXL. We might have gone overboard with this one, but getting this right surfaced a lot of latent issues and feature gaps:

- Videos can now playback audio
- Clips can have local keyframes that move with their clips
- Audio- and Video-Clips can be "auto collected" by player operators without the need to manually create connections
- [VideoClip]s now have nice thumbnails
- [AudioClip]s can be displays as Volume-level and Waveform
- Clips can be duplicated with `Ctrl+D` — like splitting, the new operator is inserted tidily into the graph and pushes covered operators down
- Texture effect operators can be inserted between a [VideoClip] and its [VideoClipPlayer]
- Video clips show a preview thumbnail on hover and at their begin and end
- The audio tracks of videos are now included when rendering / exporting videos
- Audio tracks in MKV files play back correctly
- Media clips keep their source time in seconds; BPM changes can stretch them with the beat or keep their duration
- GIF files are treated as videos
- Fixed video tearing during playback and when encoding proxy files
- Improved performance when seeking outside a clip's source range
- Rendering custom ranges with audio and exporting image sequences works reliably again, and video render-export got faster
- Changing the render codec adjusts the file extension

## Source Region Editing

The Timeline ruler can now display the extend of the source data. This source region can be dragged for intuitive slip edits. Combined operators with a time clip output can define and edit their own source range.

## Keyboard Control

Most of the graph can now be driven without a mouse. See [Keyboard Shortcuts](../docs/using/KeyboardShortcuts.md).

- The arrow keys move the selection to the neighbouring operator in the graph and scroll it into view. Subtle marks show where each arrow key leads, and the opposite key always returns the way you came. Long jumps zoom out briefly.
- **S** opens a parameter popover for the selected operator. Type to filter its parameters, use the arrow keys to move through them, and Tab to edit a value. Down applies the value and moves on, Enter applies and closes.
- Values can be typed as numbers, calculations like `*2` (continues from the current value) or `(1+2)^2`, vectors like `0 1 0`, colors like `orange` or `#f80`, and dropdown options by name.
- Left and Right adjust the focused value with the infinity slider (Shift fine, Ctrl coarse). On colors they change the brightness, or hue, saturation or a channel after typing `h`, `s` or `r g b a`.
- Shift+R resets a parameter, Shift+I inserts an operator connected to it.
- In the symbol browser, Space after an operator's name (or after picking it with the arrow keys) lists its presets. Enter inserts the operator with the preset; another Space inserts it and opens the parameter popover.
- Tab inserts an operator below the selected one and highlights where it will go; Shift+Tab inserts it to the right. Tab works whenever the graph has keyboard focus, without hovering it. A connection leaving the bottom of a stack is passed on to the new operator. Inside a stack the operators above make room, so the ones below keep their place.
- Shift and a digit bookmarks the selected operator for the project; the digit alone jumps to it, even in another composition. Bookmarked operators show their digit in the graph.
- Holding P shows the selected operator in the output window only while the key is down; a tap pins it as before. Pressing P on the pinned operator no longer unpins it.
- Short notifications in the menu bar confirm keyboard actions that have no visible result, like saving a window layout or copying operators, and point out related shortcuts. They can be turned off in the settings, where "Show Tips Again" brings the tips back.
- The graph window has keyboard focus by default and gets it back when nothing else is selected.

## Procedural Geometry

A new family of CPU geometry operators builds and modifies meshes with faces of any number of corners before they are turned into GPU buffers: [CubeGeometry], [BevelGeometry], [TransformGeometry], [TriangulateGeometry], [DisplaceGeometry], [ExplodeGeometry], [VoronoiFracture], [SeparateLooseParts], [PlaceGeometryAtPoints], [LoadObjGeometry], fields like [NoiseField] and [CustomScalarField], and [GeometryToMesh] to render the result. Heavy operations run asynchronously and restart when parameters change, and the output window shows geometry stats. See [Procedural Geometry](../docs/using/ProceduralGeometry.md).

Curves join the family: [TextToCurves] turns text into outlines, [SubdivideCurves], [CurvesToPoints] and [CurvesToGeometry] process them.

## Character Animation

TiXL can load rigged and animated glTF models, play their animation clips, blend and retouch poses, and rig your own procedural geometry to a skeleton: [SampleGltfAnimation], [BlendPoses], [AdditivePose], [OverrideJoint], [RetargetPose], [SkinMesh], [SkinPoints], [BindToSkeleton] and more. See [Character Animation](../docs/using/CharacterAnimation.md).

## Audio Beat Lock with DanceAI

In live mode, playback can now continuously lock onto the audio input. The new **Phase Model** beat lock source uses DanceAI, a small neural network self-trained by Felix Niemeyer for exactly one job: estimating bar phase and tempo of an audio stream. It runs locally in the background, needs no tapping and reports its confidence. **Beat Sync Offset** compensates for delayed video output.

## Smoother Frame Rates

- Animations, beat timing and UI motion are driven by the measured frame duration instead of assuming 60 Hz.
- Frame pacing follows the display the window is on, also with non-standard refresh rates.
- A new **Frame Rate** setting (in Settings and the Performance window) renders at a fraction of the display rate, so heavy scenes on a 120 Hz panel no longer alternate between 120 and 60 fps.
- NDI sync frames can be locked to the frame rate override.
- Fonts are rebuilt when the display scale factor changes.

## Player and Exporting

- Exported players show a startup dialog and a loading progress bar, and load faster thanks to shader caching.
- The exported executable is named after the project, and unused children are no longer exported.
- Players use the Output Setup and [SendToOutput], and can play back over NDI.
- Projects can be exported from the Project Settings window.
- The player exporter states the licensing requirements of the BASS audio library.

## MIDI Device Aliases

MIDI device names change with every unit, operating system and USB port, and every `[MidiInput]` that stored one broke with it. Projects can now store an alias such as `TiXL:ApcMini` instead. Which physical device it means is set per machine in Settings » Midi, where existing device-specific names can be replaced with an alias in one step. Teaching stores the alias, and the mapping ships as `midiAliases.json` next to an exported Player, where it can be edited on site. See [MIDI device aliases](../docs/using/MidiDeviceAliases.md).

## Snapshots and Variations

- Snapshots can be arranged in the grid layout of a MIDI controller.
- Variations can be rearranged and renamed more easily.
- Snapshot parameters that never change, or that are connected, can be removed in one step.
- The parameter control view can be used without creating a snapshot, and snapshot control can be toggled by clicking on the input area.
- Combining operators into a new symbol also transfers their snapshots.

## Improve Project Settings

We cleaned up the design and structure of the the *Project Settings* window.

## Project Folder Structure

Operators of a project now live in a dedicated `Symbols/` folder, and build output and backups moved to `.temp/`, so a project folder only shows what's yours. See [Files and Folders](../docs/install/FilesAndFolders.md).

- Asset files can be deleted from the Asset Library (they're moved to the Windows recycle bin)
- Dropping a file folder into the editor lets you create external folder references
- Broken asset folder references can now be relinked
- Files dragged in from a linked asset folder are no longer copied
- Cleaned up the visual design of the asset context menu

- Dragging a window splitter keeps the graph window focused.
- The graph shows indicator lines for auto-collected clips (e.g. [TimeClipPlayer], [AudioClip]s)
