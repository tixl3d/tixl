The bundle of state — current time, resolution, camera matrices, and shared variables — that flows down through the graph as it's evaluated each frame.

Every operator reads what it needs from this context and can hand a modified copy to the operators below it, which is how [ui:TimeOverrides|time overrides], camera settings, and custom variables reach a whole sub-graph without extra wires. When a graph gets tangled with long connections, you can set booleans, numbers, or vectors into the context once at the top and read them anywhere downstream, keeping the graph clean. Two subtle hazards live here: operators update in the order their inputs are declared, so a value read "across" the graph may lag by a frame, and reading time from the context (rather than a baked-in copy) is what keeps multi-pass effects like motion blur correct.
