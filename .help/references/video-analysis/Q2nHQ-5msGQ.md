A 3.5-hour meet-up that opens with a naming/precision discussion and a tour of the new SkillQuest tutorial system, then spends most of its length on a deep, example-driven explanation of the per-point F1/F2 spare attributes — how operators write and consume them — and ends with a live code-edit adding F1/F2 and a strength factor to an operator, plus experiments with the new normal-buffer output.

## Mentions
- 7:00→13:30 [ui:SymbolLibrary] · explained · discussion · Concept · 60% — Why a math/number namespace renamed `Value` to `Float`: a `Float` op is a precise type, not a meta-type, and the trade-off of searchability (you want it to surface when searching "value" *and* "float") drives the naming and synonym choices.
- 13:30→18:10 [ui:LocalTime] · explained · discussion · Concept · 70% — Why a long-running installation's time eventually loses smoothness: a 32-bit float can't encode enough precision after days/months, so single scalars are headed to double precision (vectors stay float because the GPU wants float).
- 19:40→33:30 [ui:SkillQuest] · explained · scripted · Concept · 80% — A non-linear, map-of-topics learning system where each level shows a hidden target output and you must rebuild it; later levels compare animated value-histories, not just images, so you must reason about the curve rather than just wire nodes.
- 33:30→36:10 [ui:SkillMap] · explained · scripted · Concept · 70% — An internal authoring tool for laying out tutorial topics as cells, setting unlock rules (complete one prerequisite vs. all of them) and styles for the quest graph.
- 36:10→47:00 [ui:Annotations] · explained · discussion · Tip · 70% — "Tour points" upgrade free-floating scene comments into an ordered, navigable walkthrough you attach to operators — select a node, add a tour point, reorder by drag — to turn an example project into a guided tutorial.
- 39:50→41:30 [ui:SymbolBrowser] · passing · discussion · Gotcha · 55% — Many operators ship without example projects; a good op deserves a browsable example so users can open and inspect a working wiring rather than guessing.
- 41:30→43:50 [Blend] · passing · scripted · Example · 60% — A shipped example wires two image inputs with the blend-mode index driven by an integer so it cycles through every mode for comparison.
- 53:30→58:20 [ui:ParameterWindow] · passing · discussion · Gotcha · 55% — Two reported UI bugs: a parameter popup opens on operators that have no animatable input, and a layout glitch appears when pinning certain operators — both cosmetic and easy to fix.
- 58:50→1:01:00 [ui:SearchWindow] · explained · scripted · Tip · 75% — Typing `?` in the operator search returns a random operator, and cycling seeds yields fresh suggestions — a way to discover unfamiliar ops or set yourself a build challenge.
- 1:01:00→1:05:30 [SetFloatVar] [GetFloatVar] · in-depth · scripted · Example · 85% — Name a variable once, then read it back anywhere with the matching getter so one source (a noise, a MIDI value, a master volume) drives many places; the setter only exists where its subgraph runs, so wire it under an [Execute] pinned first to guarantee it evaluates before its readers.
- 1:01:00→1:02:30 [RaymarchField] [SetMaterial] · explained · scripted · Example · 75% — A quick ray-march scene: feed it an SDF field and set a hard, glossy material to get a clean reflective sphere to test variable-driven parameters against.
- 1:05:30→1:10:40 [MidiInput] · in-depth · experiment · Parameters · 80% — Teach mode captures device name, event type, channel and control id only while the op is being evaluated (connected to an output) and a real MIDI signal arrives; the built-in damping smooths MIDI's coarse 127-step resolution, so disable it when you need a clean per-change trigger.
- 1:06:30→1:10:00 [Trigger] [TriggerAnim] · explained · experiment · Example · 75% — Convert a changing value into a one-shot by choosing increased/decreased/changed, then pipe the resulting boolean into an animation trigger to fire an emit or restart on each step.
- 1:10:00→1:11:00 [DirectionalForce] · passing · experiment · Tip · 60% — Driving a force's strength from a per-change trigger ramps it up smoothly over the emitted particles instead of restarting an animation from the same frame every time.
- 1:10:40→1:12:30 [PlotValueCurve] · explained · scripted · Tip · 80% — Drop it on top of a group to graph a scalar over time inside the rendered scene — invaluable for debugging exported executables where you can't just open an extra output window.
- 1:13:00→1:16:10 [ValueRaster] · in-depth · scripted · Concept · 80% — Draws a recursively subdividing grid raster whose line density follows image resolution and the chosen value range — the background grid the math quizzes use to plot curves precisely.
- 1:16:10→1:20:00 [ValuesToTexture2] · in-depth · scripted · Parameters · 80% — A redo of the bake-list-into-texture op with a clear input-range / clamp / gain-bias / output-range pipeline; use the input range to stretch a tiny value spread (e.g. 0.0–0.003) into a visible, usable texture.
- 1:16:40→1:18:50 [PointsToCPU] [GetPointDataFromList] · explained · experiment · Example · 70% — Read a GPU point buffer back to the CPU and pull an attribute (position) off it directly — you don't always need the intermediate data list.
- 1:18:50→1:19:30 [KeepFloatValues] · passing · experiment · Example · 60% — Accumulates successive scalar samples into a growing list you can then bake to a texture and visualize as a history.
- 1:21:00→1:22:50 [AnalyzeFloatList] · explained · scripted · Example · 70% — Feeds the quiz curve plotter: it derives the min/max range of a float list, padded a little, so the same range scales both the raster and the drawn curve consistently.
- 1:23:30→1:42:20 [ui:Field] · in-depth · answer · Concept · 85% — The core F1/F2 explanation: a TiXL point is a fixed 64-byte GPU struct (position, rotation, color, scale) where the unused 4th lanes of two 3-component vectors leave two spare float attributes; every generator, modifier and consumer can write or read F1/F2, making them a universal channel for masks and side effects.
- 1:26:30→1:29:00 [AddNoise] · explained · answer · Parameters · 75% — Most point modifiers expose a strength plus an F1/F2 picker that defaults to 1 (a neutral factor); pick F1 to gate the displacement per-point by a mask written upstream, or drive the noise amount from it.
- 1:29:00→1:34:00 [SelectPoints] [SelectPointsWithSDF] · in-depth · answer · Comparison · 85% — Write a 0/1 mask into F1/F2 from whether a point sits inside a shape; the SDF variant binds the test to any distance field (a torus, noise-displaced) instead of the legacy fixed sphere, making it far more expressive as a selector.
- 1:32:00→1:33:40 [TransformPoints] · explained · answer · Example · 80% — Apply a move/rotate to every point but scale it by the F1 factor so only masked points actually shift — the canonical "modify only the selection" pattern.
- 1:34:00→1:39:00 [MapPointAttributes] · in-depth · answer · Concept · 80% — A meta-mapper that binds a chosen source (buffer order, F1/F2, random, particle age) to a target (color via gradient, scale, fade) — e.g. colorize points by the F1 mask an upstream SDF wrote, with a multiply color mode that's neutral at 1.
- 1:40:00→1:42:20 [OrientPoints] · explained · experiment · Example · 70% — Orients points toward a center, gated by an F1 mask so only points inside a torus get reoriented; pair it with a [Vector3Gizmo] to see and move the target.
- 1:44:30→1:53:00 [LinearSamplePointAttributes] · in-depth · answer · Parameters · 80% — Ignores point world-position and samples a texture/gradient purely by buffer order; right-click the gradient handle to switch interpolation from linear to smooth, and the "blend" stop mode splits the ramp into Photoshop-curve-like zones.
- 1:53:00→1:59:00 [RemapColor] · explained · scripted · Example · 75% — A glue op between an input texture and a gradient: switch to spline interpolation and insert handles to reshape contrast like a Photoshop curves adjustment.
- 1:57:00→1:59:00 [TransformPoints] · explained · experiment · Gotcha · 75% — Why rotating points around an axis seems to do nothing at the origin: scale→rotate→translate order means object-space rotation has no visible effect until you offset the center; converting to a single quaternion matrix also prevents multi-turn (helix) results.
- 2:03:00→2:13:30 [PointsOnMesh] · in-depth · experiment · Example · 80% — Scatter 100k points over a mesh, then use F1 (a plane-distance SDF mask) to drive a peel-away reveal: displace along normals by the mask, fade via [MapPointAttributes] gradient, add masked noise, and bloom the bright tips into a burning dissolve.
- 2:04:30→2:05:30 [SelectPointsWithSDF] · explained · experiment · Tip · 70% — Using a plane SDF as a near-linear ramp: distance-to-plane grows with height, so it behaves like a gradient you can feed into F1 for size or displacement without a texture.
- 2:09:00→2:10:00 [DrawPointsShaded] · passing · experiment · Tip · 55% — Swapping plain point drawing for the shaded variant gives the scattered points lit volume for the burning-reveal look.
- 2:16:00→2:22:00 [ParticleSystem] · in-depth · experiment · Example · 75% — Emit particles off a mesh's points so they fly along the surface normals; the system writes particle age into F1, which [MapPointAttributes] then maps onto a glow gradient so particles brighten as they age.
- 2:19:30→2:21:00 [DrawMovingPoints] · passing · experiment · Tip · 55% — Draws emitted particles with motion so the flying points read as streaks rather than static dots.
- 2:23:00→2:25:00 [MeshVerticesToPoints] · explained · discussion · Concept · 70% — A mesh is an index buffer plus a vertex buffer; converting its vertices to points (and visualizing them) reveals that hard corners duplicate vertices because they can't share a normal across edges.
- 2:24:00→2:25:00 [SelectVertices] · passing · discussion · Comparison · 55% — Exists for meshes but its selection semantics differ from the point F1/F2 model, which is why an F1/F2-style mesh selector that points could inherit is still wished-for.
- 2:26:00→2:35:00 [TextureMapForce] · in-depth · experiment · Example · 70% — Push particles using a texture as a force field; feeding it a rendered normal buffer pushes particles off surfaces, but the force maps to screen space, not world space — a step toward depth-buffer/normal-based collision like game engines do.
- 2:29:00→2:34:00 [NormalMap] · explained · experiment · Gotcha · 65% — Generating a normal map (rgb-signed mode) from a render to drive forces — but the produced map comes out flipped vertically versus the geometry's own normal buffer, a bug noted live.
- 2:38:00→2:41:00 [DetectEdges] · explained · experiment · Comparison · 80% — Running edge detection on the scene's normal buffer instead of the color image yields much cleaner, sharper edges — the normals change abruptly at creases even where color doesn't.
- 2:50:00→2:57:30 [CustomPixelShader] · in-depth · experiment · Example · 70% — Sample the scene normal buffer in a custom pixel shader and dot it against a fixed view vector to build a Fresnel-style rim glow; `1 - dot` gives the edge falloff, a power param tunes intensity, and `discard` on zero-length normals removes the background.
- 2:50:00→2:51:00 [Bloom] · passing · experiment · Tip · 55% — A post bloom over the masked bright tips is what sells the glow/burn looks built earlier — easy to overdo.
- 3:00:00→3:27:00 [LinearSamplePointAttributes] · in-depth · experiment · Concept · 75% — Live code-edit migrating an operator off the legacy point struct and the old W naming: add F1/F2 enum entries (appended, never inserted, to keep old projects working), move flags into an int buffer to avoid float-compare bugs, and apply the sampled value additively or multiplicatively per the mode.
- 3:19:00→3:28:00 [TransformPoints] · in-depth · experiment · Tip · 70% — Adding a universal strength factor by lerping every modified field (position, scale via lerp, rotation via spherical quaternion lerp, F1/F2) against the original by a strength parameter, so any effect can fade in or be exaggerated/negated from a neutral default of 1.
