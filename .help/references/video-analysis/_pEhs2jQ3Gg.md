An unstructured beginner webinar walking through TiXL's evaluation context: how time (in musical bars) and the "magic" 0,0 resolution flow backwards from the output, how image operators chain and blend, HDR colours, the gain/bias mapping curve, and a closing live experiment building a particle "black hole".

## Mentions
- 0:03→0:18 [ui:EvaluationContext] · explained · scripted · Concept · 88% — The pull model that drives everything: data wires point toward the output, but evaluation starts at the pinned output and walks backwards, each operator reading time, resolution, camera, material and light from a shared context it must restore afterward.
- 0:18→1:24 [ui:LocalTime] · in-depth · scripted · Concept · 90% — Time is measured in musical bars, not seconds: four beats per bar, one bar ≈ 2s at 120 BPM, so animation rates expressed in bars stay locked to the beat while still drifting in longer cycles.
- 1:24→2:05 [ui:Timeline] · explained · scripted · Tip · 78% — Scrubbing with the left mouse jumps playback; releasing lets time continue forward from that point, which lets you preview a moment then keep rolling.
- 5:55→7:18 [LoadSoundtrack] · passing · scripted · Tip · 70% — Add it to a project to override the default 120 BPM so every bar-based animation re-times to the track's tempo.
- 7:35→8:53 [Time] · explained · scripted · Concept · 80% — Its "always evaluated" output flag forces re-evaluation every frame wherever it's wired, which is how a downstream operator keeps reading the live playhead instead of a cached value.
- 9:24→11:17 [SetTime] · in-depth · scripted · Example · 88% — Freezes or remaps the playhead for everything drawn after it, so you can drive a sub-scene's animation from any value (e.g. a wave) and play that segment deterministically forward and backward.
- 11:17→13:50 [SetTime] [Transform] · explained · scripted · Example · 82% — Render one scene twice with offset clocks: duplicate the group, feed each copy a different time so the same deterministic animation appears at two phases at once.
- 13:50→16:10 [RenderWithMotionBlur] · explained · scripted · Performance · 84% — Accumulates several sub-frame passes at slightly offset times for true long-exposure blur (no post fake); cost scales with pass count, so preview cheap and crank passes only at final render.
- 20:30→27:30 [ui:OutputSettings] · in-depth · scripted · Concept · 86% — The "magic" 0,0 resolution: take the incoming image's size if one is connected, else the output window's; aspect is preserved by cropping left/right, never top/bottom.
- 21:46→22:30 [ImageLevels] · explained · scripted · Tip · 82% — Reads out the actual intensity along a slice as a graph overlay, a quick way to verify whether a gradient really reaches 0 and 1 or is clipped short.
- 22:30→25:05 [LinearGradient] · explained · scripted · Parameters · 80% — Size-mode "align to height" vs. "align to width" decides which axis the gradient spans as the canvas aspect changes; align-to-height keeps a circle drawn over it perfectly round at any resolution.
- 26:40→33:50 [SetRequestedResolution] · in-depth · scripted · Concept · 85% — Overrides the requested resolution carried in the context: positive values force a fixed size for all downstream 0,0 operators, negative values fall back to the output window, letting a post chain ignore an odd incoming image size.
- 28:40→31:00 [Raster] · explained · scripted · Example · 78% — Give it an explicit resolution to draw a crisp high-res overlay on top of a deliberately low-res background image, decoupling the effect's detail from the source's pixel count.
- 33:58→35:40 [RenderTarget] · explained · scripted · Concept · 80% — Its 0,0 resolution makes a sub-scene render at whatever size the consumer asks for, so the same graph is sharp at 480p or 8k without edits.
- 35:00→35:40 [ScaleResolution] · passing · scripted · Tip · 72% — Stack it in a chain to multiply the incoming requested resolution by a factor (e.g. ×4) rather than typing absolute pixels.
- 35:53→41:02 [Layer2d] · explained · discussion · Gotcha · 80% — It draws a texture as a camera-facing quad whose aspect follows the texture's own resolution, so a screen-in-scene squashes when the canvas changes unless you pin the source to a fixed resolution.
- 41:02→45:10 [DrawPoints] [UseFallbackTexture] · in-depth · experiment · Gotcha · 82% — Each point is a billboard stretched to the sprite texture's aspect, so a non-square sprite makes the dots elliptical and canvas-dependent; dive in to find the fallback sprite and set its source a fixed square resolution.
- 41:45→42:00 [ui:Gizmo] · passing · experiment · Gotcha · 60% — Disabling z-write/z-test removes back-point cut-off artefacts from alpha-cutout sprites, but you usually still want z-testing.
- 45:40→50:05 [RoundedRect] · in-depth · scripted · Parameters · 84% — Roundness 1 turns the rect into a circle and stroke-only (no fill/background) gives a ring; enabling its mip-map generation is what fixes the shimmer when the shape is later minified by a camera.
- 48:00→50:05 [ui:Asset] · explained · scripted · Performance · 75% — Mip-maps store pre-scaled copies so a minified sprite samples a blurred level instead of aliasing; off by default for the small cost, only worth it when a textured thing changes size on screen (particles being the classic case).
- 51:05→55:46 [ui:SymbolLibrary] · explained · scripted · Tip · 80% — The pinnable browser groups symbols by namespace; "examples" holds the walk-through how-to operators worth dragging out and double-clicking, and "lib" holds the built-ins sorted by category (field, image, mesh, points…).
- 55:46→59:00 [Blob] · explained · scripted · Example · 78% — Stack two image operators and they auto-snap into a chain that composites foreground over background at the target resolution; feathering the edge and dragging brightness down removes the colour fringe between fore- and background.
- 58:35→1:00:00 [Grain] · passing · experiment · Gotcha · 68% — Adds noise structure to an opaque image but does nothing useful on a transparent one, so apply it before things go transparent.
- 1:00:00→1:02:30 [ui:Graph] · explained · scripted · Tip · 76% — In a vertical operator stack you can long-press-drag a member out of the chain, or drop a new one between two blinking insert lines to control exactly where in the render order it lands.
- 1:04:30→1:11:00 [ChannelMixer] · explained · experiment · Tip · 72% — Its "alpha to grayscale" preset visualises the alpha channel as brightness, revealing that stacked semi-transparent blobs approach but never reach full opacity.
- 1:08:00→1:10:30 [ui:ColorEditor] · explained · scripted · Gotcha · 78% — A pixel keeps its RGB colour even where alpha is 0, so a transparent foreground can still bleed coloured fringes; match fore- and background colour (e.g. both black) to avoid them.
- 1:10:30→1:18:00 [Blend] · in-depth · scripted · Parameters · 84% — Two-input compositor with separate colour and alpha blend modes plus per-input colour multipliers; mismatching the two modes (screen colour, normal alpha) is what makes opacity seem ignored.
- 1:13:00→1:18:00 [GetImageBrightness] · passing · scripted · Tip · 66% — Can drive the alpha-blend term so a layer's own brightness decides its transparency, useful for masking from luminance.
- 1:12:00→1:13:00 [ui:ParameterWindow] · passing · experiment · Tip · 58% — Hold Ctrl over an enum/number field (outline turns blue) to scroll through its values with the mouse wheel.
- 1:18:00→1:24:00 [BlendWithMask] · explained · scripted · Comparison · 74% — Use plain [Blend] when you just want A over B; reach for the mask variant only when a separate image should gate where the blend happens.
- 1:20:30→1:25:30 [ui:Composition] · in-depth · scripted · Concept · 80% — Overlay blend mode leaves mid-grey untouched while pushing shadows darker and highlights lighter, acting like a contrast/structure boost when you composite noise or a second image at low opacity.
- 1:24:50→1:30:00 [ui:RenderSettings] · in-depth · scripted · Concept · 82% — Geometry draw operators expose a hardware blend mode (normal/additive/invert…) that controls how the drawn pixels combine with what's already in the render target — additive on a black background reads as transparent, but a correct multiply isn't available there.
- 1:30:00→1:35:00 [DrawBillboards] · explained · experiment · Tip · 74% — Unlike camera-locked point sprites, billboards can be rotated in point space, so feeding rotated squares into an invert blend yields kaleidoscopic tile patterns.
- 1:32:00→1:33:20 [GridPoints] · passing · experiment · Example · 70% — A flat grid of small sprites drawn with invert blend turns into a self-overlapping tile pattern as the dots grow and overlap.
- 1:34:00→1:36:25 [TransformPoints] [SelectPointsWithSDF] · explained · experiment · Example · 78% — Drive its strength factor from an F-attribute set by a sphere SDF selection so the rotation/translation only applies to points inside the field region.
- 1:37:00→1:44:00 [ui:ColorEditor] · in-depth · scripted · Concept · 85% — TiXL renders into RGBA16, so colours can exceed 1.0; Ctrl-drag a swatch upward past white to make an HDR value (the up-arrow marker), which is what gives [Bloom] and emissive materials their punch.
- 1:40:00→1:44:00 [Bloom] · explained · scripted · Example · 80% — Glows only from areas brighter than 1.0, so pair it with HDR colours (e.g. an HDR step in a material's gradient) to make just the bright bands of a surface bleed light.
- 1:42:50→1:46:20 [ToneMapping] · in-depth · scripted · Concept · 84% — Pulls clipped super-bright HDR values back into range; the AGX mode blends smoothly toward white instead of letting channels rail to pure R/G/B, avoiding the harsh cut-off look on intense colours.
- 1:44:11→1:46:20 [WaveForm] · explained · scripted · Concept · 76% — Its vectorscope plots the image's colours around a hue wheel, exposing how extreme colours snap onto the RGB primaries — the artefact AGX tone-mapping smooths out.
- 1:46:20→1:59:40 [ui:ParameterWindow] · in-depth · scripted · Concept · 88% — The gain/bias vector2 found on many operators is a remap curve: bias shifts the midpoint toward dark or light, gain bends it toward an S-curve (more contrast) or its inverse, letting you reposition and harden a gradient edge playfully instead of editing keys.
- 1:53:00→1:55:00 [FractalNoise] · passing · scripted · Tip · 72% — Push its gain/bias toward high contrast to threshold the noise into leopard-like blotches, then ease off for softer edges.
- 1:53:40→1:59:00 [RadialGradient] · passing · scripted · Tip · 70% — Gain/bias reshapes the falloff to get a tight bright core that tapers out, e.g. a glowing star centre.
- 1:54:00→1:59:00 [Bloom] · explained · scripted · Parameters · 80% — Its internal gradient colours the successive blur levels by distance from the source — and accepts transparent steps — so you can tint the outer glow a different hue or cut the core entirely for an underwater halo.
- 1:59:40→2:02:20 [RemapColor] · in-depth · scripted · Parameters · 82% — Maps each input colour through a gradient per-channel or in grayscale; a hold-interpolated step makes a threshold, and its own gain/bias positions where that threshold falls.
- 2:02:20→2:07:10 [RandomizePoints] · in-depth · scripted · Parameters · 84% — Scatters points along their orientation (z = surface normal) and its gain/bias controls the distribution of the offset, so most points cluster at the outer shell while a few reach far, giving an animated shimmering surface.
- 2:02:40→2:03:20 [PointsOnMesh] · passing · scripted · Example · 72% — Scatters points across a mesh surface (here a sphere) as the raw material for sparkles or particle emission.
- 2:11:00→2:14:00 [ParticleSystem] · in-depth · experiment · Parameters · 80% — Emit-once from input points with a long lifetime; lifetime −1 auto-derives a value from input-count over buffer size, and points carry a default emit velocity so they drift outward even with no force (negative velocity fires them inward through the centre).
- 2:16:00→2:19:30 [ParticleSystem] · explained · experiment · Gotcha · 72% — A constant emit seed leaves streaks (same points re-emitted each frame) while a changing seed scatters fresh positions; buffer size vs. emit count caps how many simulation steps each particle survives.
- 2:19:30→2:20:30 [TurbulenceForce] · explained · experiment · Example · 76% — Adds swirling motion that intensifies over a particle's life, eventually dissolving the shape into noise once it dominates.
- 2:20:30→2:23:30 [FieldVolumeForce] [CombineSDF] · in-depth · experiment · Example · 82% — Combine several sphere SDFs into one field and feed it as a force to pull particles toward the SDF surfaces; zero the drag and disable collision reflection for an orbiting two/three-body attractor.
- 2:30:00→2:33:20 [SelectPointsWithSDF] [TransformPoints] · in-depth · experiment · Example · 80% — Select points by a plane SDF and use the selection attribute as a per-point strength factor in a transform, so only points to one side of the plane get squished or rotated.
- 2:32:30→2:33:20 [PointTrail] · explained · experiment · Example · 74% — Records each point's recent positions so [DrawLines] can render motion trails behind animated points.
- 2:33:00→2:34:10 [AddNoise] · explained · experiment · Tip · 74% — Stacking it on a point set after a field selection lets the selection attribute scale the noise amount, so displacement is strong near a centre and fades outward.
- 2:33:50→2:34:10 [SetFog] · passing · experiment · Tip · 70% — A quick way to add depth cueing to a 3D scene before rendering it to texture.
- 2:34:30→2:41:30 [SamplePointColorAttributes] · explained · experiment · Example · 70% — Pipeline to colour points by a field's distance: select with an SDF, then map the distance attribute through a gradient ([SDFToColor]) to make an inner glow region.
- 2:48:30→2:52:20 [ReflectField] · in-depth · experiment · Tip · 78% — Reflect a plane SDF to turn a half-space selection into a single thin slice, so an effect driven by that selection affects only points near the plane's centre rather than everything above it.
- 2:50:50→2:51:10 [GridPoints] · passing · experiment · Concept · 66% — Visualising a plane-SDF selection as point size shows it selects everything below the plane, not just the intersecting layer.
- 2:53:00→3:00:00 [DepthOfField] · explained · experiment · Tip · 76% — Applied after a composite/blend it can still blur by depth using the scene's depth buffer, so you composite first and rack focus afterward; pair with a focus distance to fuse a 2D edge-pass into the 3D image.
- 2:54:00→2:55:00 [ui:Composition] · passing · discussion · Comparison · 55% — TiXL's feedback is built to keep intensity in a meaningful range rather than blowing out to widescreen, but it stays hard to control precisely.
- 3:02:00→3:05:00 [TemporalAccumulation] · explained · experiment · Concept · 76% — A built-in feedback blend of the previous frame with the incoming one: a high blend factor smears fast motion into soft trails, useful for taming jittery animation.
- 3:04:30→3:09:20 [Displace] [RyojiPattern1] · in-depth · experiment · Parameters · 80% — Drive image displacement from any grayscale source; its modes choose between gradient-based and intensity-based directional push, and feeding a generated pattern yields controllable glitch distortion.
- 3:09:20→3:12:00 [RemapColor] · passing · experiment · Example · 68% — Recolour a displacement/glitch pass into a single tint (black-to-orange) before blending it back over the original.
- 3:11:00→3:13:00 [DetectEdges] · explained · experiment · Example · 74% — Use an edge-detection pass as a mask so a glitch displacement only bites at object outlines.
- 3:14:00→3:16:30 [Combine3Images] [TransformImage] · in-depth · experiment · Example · 80% — Feed a separately transformed copy of the same image into each of R, G and B to build a manual chromatic-aberration / RGB-split glitch.
- 3:16:30→3:21:00 [ReuseCamera] · in-depth · answer · Example · 84% — Pull a camera reference from a camera operator's extra output and replay it on a second sub-scene so both render from the identical viewpoint, then composite them (one edge-detected, one plain) in post.
- 3:21:30→3:24:00 [DepthBufferAsGrayScale] · explained · answer · Gotcha · 74% — Exposes the z-buffer as an image you can feed into a mask blend to do per-depth post selection, the workaround for the missing per-object ID pass.
