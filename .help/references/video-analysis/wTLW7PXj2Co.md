A long, exploratory TiXL meet-up: reworking the BubbleZoom magnifier parameters, reviewing the PR workflow, fixing an old feedback logo, dissecting the shadow render pipeline, debugging back-face shading and equirectangular point rendering, walking through custom-shader authoring with RenderDoc, and a deep live experiment building an "infinite zoom" scene-transition.

## Mentions
- 0:45→3:30 [BubbleZoom] · explained · discussion · Parameters · 72% — A flip/inversion parameter is redundant once the magnification factor can go negative; reach for one or the other, not both, to invert the lens.
- 3:30→5:20 [BubbleZoom] · explained · discussion · Parameters · 70% — The edge/feather width controls how soft the lens rim is (0 = hard cut), while radius sets the inner magnified disc — pair a feather with its gradient so the two read as related.
- 6:00→7:55 [BubbleZoom] · in-depth · discussion · Example · 80% — Feed it a gradient that runs transparent→white→transparent and the magnifier becomes a free soft-edged bubble; tint the first gradient stop opaque to fill the lens with color.
- 9:00→9:20 [BubbleZoom] · passing · discussion · Gotcha · 60% — Its magnification shifts the UVs relative to the center, so zoom is not anchored to the lens center — a shader-side fix to keep it centered.
- 13:30→18:00 [LinearGradient] · explained · experiment · Gotcha · 68% — Renaming a gradient input on an operator that exposes a gradient (a reference-typed value) crashes the symbol update; rename it in the code/source instead. Also: apply contrast as gain-then-bias, matching this operator as the canonical reference.
- 42:00→45:10 [ui:Graph] · explained · discussion · Tip · 78% — Lay post-processing chains out as vertical stacks for readability, and don't cram operators into tight gaps just because they snap — your future self has to read it.
- 44:30→45:30 [Group] [Execute] · explained · discussion · Comparison · 82% — Both bundle a sub-network; pick [Group] when you need transform plus fade-in/out, pick [Execute] when you only want enable/disable or to merge inputs — it's lighter because it carries no transform parameters.
- 43:00→47:50 [FluidFeedback] · in-depth · experiment · Gotcha · 80% — Always pin it to a fixed resolution: as a pixel-space effect its look changes wildly between 2K and 4K, so feedback amount and displacement that were tuned at one size break at another.
- 46:00→48:40 [FluidFeedback] · explained · experiment · Parameters · 70% — Animate only the reset toggle (1→0 at the start) to clear the buffer; a too-negative shade pumps the brightness until the feedback blows out, so dial shade and displacement back to tame it.
- 56:00→1:04:10 [SetShadow] · in-depth · discussion · Concept · 82% — A two-pass shadow setup: pass one builds a depth map by rendering the scene from the light's position as a camera, pass two puts that shadow texture into the context so the geometry, drawn again, can test against it.
- 59:20→1:01:30 [PointLight] · explained · experiment · Concept · 75% — Writes up to eight light positions into the evaluation context, which downstream shadow and material operators read — break the position out into a [Vector3Gizmo] to drag the light interactively.
- 1:00:00→1:04:00 [DrawMeshWithShadow] · in-depth · experiment · Example · 80% — Drop any mesh into the shadowed group and it casts and receives consistently because it checks whether the current pass is the shadow pass: on the shadow pass it just writes depth, otherwise it samples the shadow map from the context.
- 1:04:30→1:08:40 [DrawMeshWithShadow] · explained · discussion · Performance · 68% — Operators that merely draw depth get shadows "for free" without shadow-pass-specific code, but they still run their full fragment shader on the depth pass — wasteful, since the depth map needs no shading or normals.
- 1:18:50→1:19:30 [DrawMeshAtPoints] · passing · experiment · Gotcha · 66% — Can't be the first node off a render source because its first input is the mesh, not the command — a wiring order quirk to watch for.
- 1:12:50→1:17:00 [Equirectangle] · explained · experiment · Concept · 72% — Renders a scene to a 360° environment map by looping several cameras into viewport regions of one large texture; just plug a group in, no camera needed — inserting your own camera between transform and it scrambles the projections.
- 1:20:30→1:24:50 [DrawPointsShaded] · in-depth · discussion · Gotcha · 78% — Inside multi-camera renders like [Equirectangle] its billboards shade wrong because the PBR view direction is taken as a fixed camera-facing vector instead of being recomputed per camera — a real shading bug, not a renderer fault.
- 1:25:30→1:27:00 [ReuseCamera] · explained · answer · Tip · 68% — To build a fisheye/distortion rig without breaking projections, copy this node and set the reference as an object transform rather than as the active camera, so the matrix rotates geometry instead of replacing the view.
- 1:33:00→1:38:00 [TorusMesh] · explained · experiment · Example · 70% — For an endless-tunnel illusion put the camera inside the torus, rotate only on one axis, and scroll the surface texture rather than moving the camera — give it negative/inverted thickness so you're looking at the inside wall.
- 1:45:30→1:47:00 [FlipNormals] · in-depth · discussion · Gotcha · 85% — It flips the shading normals but does NOT reverse the triangle winding, so back-face culling still drops the same faces — unlike Blender's flip, so it won't single-handedly make an inside-out mesh render solid.
- 1:47:00→1:48:40 [CombineMeshes] · explained · experiment · Example · 70% — A poor-man's solidify: combine a mesh with a normal-flipped copy of itself so both sides render — though here it exposes that [FlipNormals] doesn't flip winding, so the trick stalls.
- 1:49:30→1:53:00 [ui:Field] · explained · experiment · Gotcha · 70% — With a point light inside an inverted/back-facing mesh, specular highlights vanish while diffuse still shows — the PBR shader doesn't flip the normal for back-facing triangles; a reproducible rendering bug worth filing.
- 1:46:40→1:47:00 [FlipNormals] · passing · answer · Tip · 75% — Slot it right after the mesh to fix lighting when a point light sits inside a tube, because you're then shading the back faces.
- 1:58:00→1:59:50 [ExtrudeCurves] · explained · answer · Gotcha · 76% — When you add an input parameter (here a scale factor that varies line thickness) you must triple-check it's actually wired to its [IntToFloat]/conversion node — an easy-to-miss disconnect after a version update.
- 2:05:30→2:07:30 [DetectEdges] · explained · scripted · Parameters · 70% — Feed it a blurred noise pushed through [Steps] to get hard edges first; sample-radius, strength and contrast each shape the result, and a bias/gain knob would make a useful addition.
